# Student PDF Report Service (`go-service`)

A standalone Go microservice that generates **PDF reports for students** by
consuming the existing Node.js School Management backend API. It **never touches
the database directly** — it authenticates against the Node backend, fetches the
student via `GET /api/v1/students/:id`, and renders a downloadable PDF.

> Solves **Problem 4** of the skill test.

## Endpoint

```
GET /api/v1/students/{id}/report   ->  200 application/pdf (attachment)
```

Error responses use the same `{ "error": "..." }` envelope as the Node backend
and map cleanly to status codes: `400`, `401`, `404`, `502` (upstream failure),
`500`. A `GET /healthz` liveness endpoint is also exposed.

## Architecture (hexagonal)

```
cmd/ (cobra)  ──►  internal/app (wire composition root)
                         │
        ┌────────────────┼─────────────────────────┐
        ▼                ▼                           ▼
 internal/server   internal/usecase           internal/adapter
 (generated HTTP   (GenerateReport)      ┌── HTTPStudentRepository ─► pkg/api/upstream ─► Node.js
  strict server)         │               └── PDFReportGenerator ────► pkg/pdf (fpdf + otel)
                         ▼
                  internal/port  (StudentRepository, ReportGenerator)
                  internal/domain (Student, Report)
```

- **`internal/domain`** — pure business entities (`Student`, `Report`) + sentinel errors.
- **`internal/port`** — the ports (interfaces): `StudentRepository`, `ReportGenerator`.
- **`internal/usecase`** — `GenerateReport`: fetch student → render report.
- **`internal/adapter`** — `HTTPStudentRepository` (upstream client + auth) and
  `PDFReportGenerator`, plus a **registry** that builds adapters by name.
- **`internal/server`** — oapi-codegen strict server + otel HTTP instrumentation.
- **`internal/app`** — [`goforj/wire`](https://github.com/goforj/wire) composition root.
- **`pkg/api`** — generated clients (`upstream` = Node, `report` = this service),
  with configurable retries via `hashicorp/go-retryablehttp`.
- **`pkg/pdf`** — a thin, telemetry-instrumented wrapper over the PDF library
  (no business logic).
- **`pkg/semconv`** — OpenTelemetry attributes **generated by Weaver** from
  `semconv/registry`, plus git-populated build info.

## Configuration

Config is loaded with [`koanf`](https://github.com/knadh/koanf) from a YAML file
(`configs/config.yaml`), with `REPORT_`-prefixed environment overrides. Adapters
are selected by name so you can switch implementations without code changes:

```yaml
adapters:
  student_repository:
    type: http            # adapter name
    http:                 # settings for that adapter
      base_url: http://localhost:5007
      username: admin@school-admin.com
      password: 3OU4zn3q6Zh9
      retry: { max_retries: 3, wait_min: 200ms, wait_max: 2s }
  report_generator:
    type: pdf
    pdf:
      title: Student Report
      organization: Greenwood High School
```

## Development

This project follows **TDD** and the mandatory workflow in the repo-root
[`AGENTS.md`](../AGENTS.md). Requires **Go 1.26.5**, Docker, and (for regenerating
semantic conventions) the `otel/weaver` image.

```bash
make help              # list targets
make generate          # oapi-codegen + wire + mockgen
make semconv           # regenerate pkg/semconv from the Weaver registry
make check             # fmt + lint + unit tests (with coverage)
make build             # build ./bin/report-service with build-info ldflags
make run               # run the service (serve)
make test-integration  # testcontainers integration suite (real Node + Postgres)
make compose-up        # run the whole stack locally (postgres + node + service)
```

- **Unit tests** use [`go.uber.org/mock`](https://github.com/uber-go/mock)
  (gomock) — never hand-rolled mocks.
- **Integration tests** (`tests/integration`, `-tags=integration`) use **no
  mocks**: they spin up real Postgres + the real Node backend + this service
  (built in Docker) via testcontainers, validate responses against the OpenAPI
  spec, and write sample student PDFs to `tests/integration/artifacts/`.
